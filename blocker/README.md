# `blocker/` — Astra's ad, tracker and malware blocker (source of truth)

This directory is the only place the blocker is edited. The engine sources,
the filter catalog, the scriptlet/redirect resources and the offline seed live
here. `forge overlay` stages them into the fetched engine tree, and
`forge export` regenerates the patch bodies from that tree. **Never** edit
`engine/toolkit/components/astra_blocker_engine/` or a `patches/*.patch` body
directly: both are derived and are replaced on the next rebuild.

## Upstream (reference clones, git-ignored under `folder_context/`)

| Repository | What Astra takes | What it does not take |
|---|---|---|
| [`brave/adblock-rust`](https://github.com/brave/adblock-rust) | The matching engine, already vendored by Gecko as `adblock 0.12.1` (also used by Mozilla's content classifier) | Its JavaScript bindings, npm packaging, benches |
| [`brave/adblock-resources`](https://github.com/brave/adblock-resources) | The generic scriptlet/redirect resources (VAFT, video-swap, de-AMP, touch-fix, trusted types) | Brave product scriptlets (`brave-*`), SugarCoat bundles, Brave-branded metadata |
| [`brave/adblock-lists`](https://github.com/brave/adblock-lists) | Catalog structure and list-selection knowledge | Brave-owned lists (`brave-*.txt`), Brave service allow-rules, Brave update hosts |
| [`brave/adblock-lists-mirror`](https://github.com/brave/adblock-lists-mirror) | Nothing at runtime; its commits are recorded for provenance | Its generated mirror files |

The exact commits and the adblock-rust version are recorded in
`lists/catalog.json` → `upstream`.


## Rebranding and data policy

`blocker/tools/sync.py` enforces the rules that keep Brave out of the product:

- Brave-owned list sources (`raw.githubusercontent.com/brave/**`,
  `github.com/brave/**`, `brave.com`, `bravesoftware.com`, `brave.software`)
  are dropped, not merely renamed. They carry Brave service filters, Brave
  update hosts and statcounter allowances that must not answer inside Astra.
- The catalog title, group and source URL of every shipped list are checked
  against `brave|rewards|telemetry|p3a|analytics`; a match fails the import.
- Brave product resource families (`brave-*`, `async-sugarcoat-*`) are
  dropped. Only generic uBlock-style resources remain.
- There is no Brave rewards, telemetry, analytics, P3A, sync or update client
  anywhere in the native component or the host module. The only network calls
  are explicit HTTPS filter-list fetches to the upstream URLs in the catalog.

## Update workflow

```sh
# 1. Refresh the reference clones (folder_context is git-ignored)
cd folder_context/adblock-rust && git pull --ff-only
cd ../adblock-resources && git pull --ff-only
cd ../adblock-lists && git pull --ff-only
cd ../adblock-lists-mirror && git pull --ff-only

# 2. Regenerate the Astra-owned data (deterministic; fails on branding leaks)
python3 blocker/tools/sync.py
python3 blocker/tools/sync.py --check     # CI gate

# 3. Stage the engine component and shipped data
(cd forge/astra-forge && cargo run -q -- overlay)

# 4. Regenerate the patch body from the staged tree (never hand-edit it)
(cd forge/astra-forge && cargo run -q -- export)
(cd forge/astra-forge && cargo run -q -- lint && cargo run -q -- footprint)

# 5. Rebuild and prove it in the running browser
(cd forge/astra-forge && cargo run -q -- build --jobs 2)   # never omit --jobs 2
python3 tools/marionette-probe/blocker-probe.py
```

## Runtime architecture

```
nsHttpChannel
  └─ AsyncUrlChannelClassifier::CheckChannelHelper        ASTRA-0005 hook
       └─ mozilla::AstraBlocker::ShouldBlockChannel
            └─ astra_blocker_engine_should_block           Rust FFI
                 ├─ per-site pause check
                 ├─ adblock-rust network match
                 └─ counters (never URLs/origins; private = no count)

Chrome JS (Blocker.sys.mjs)
  ├─ catalog + on-disk cache + HTTPS fetches + scheduler (nsITimer)
  ├─ @astra/blocker;1 nsIAstraBlockerService
  │    ├─ installRules(text)      compiles once, swaps only on success
  │    ├─ setResources(json)      scriptlets/redirects
  │    ├─ cosmeticFor(url, …)     CSS + procedural + injected script
  │    └─ stats()/resetStats()
  └─ AstraBlocker actor
       ├─ parent: engine lookup (chrome process)
       └─ child: injects CSS/script/procedural actions into the page
```

One compiled engine is shared by the network hook and chrome. `Engine` is
`!Send` under Gecko's `single-thread` feature, so the Rust crate keeps it in a
main-thread-guarded slot; every entry point checks `NS_IsMainThread()` and
fails open off-thread. There is no second engine, no sidecar process and no
per-request thread hop in the steady state.

## Settings and schedule

`astra.blocker.*` prefs are the durable state:

| Pref | Default | Meaning |
|---|---|---|
| `astra.blocker.enabled` | `true` | Global switch |
| `astra.blocker.lists` | catalog defaults | JSON array of enabled list ids |
| `astra.blocker.update-hours` | `24` | Check interval in hours; `0` = manual only |
| `astra.blocker.update-on-startup` | `true` | Catch up when a check was missed |
| `astra.blocker.cosmetic` | `true` | Inject CSS/procedural hiding |
| `astra.blocker.scriptlets` | `true` | Run `+js(...)` resources |
| `astra.blocker.last-update` | — | Unix seconds of the last successful install |
| `astra.blocker.installed` | — | JSON manifest (revision, per-list bytes/sha256) |
| `astra.blocker.site-exceptions` | `[]` | JSON array of paused hosts |

The Settings page (`Privacy` → Ad, tracker and malware protection) edits these
through `blocker_configure`; "Update lists now" uses `blocker_refresh_sources`.
A failed fetch or compile keeps the previous engine and reports the failure;
it never leaves protection off.

## Performance / memory

- One engine instance for all lists; the native service compiles on the main
  thread only when rules change (boot/update), not per request.
- Candidate requests are matched in memory before connect; no allocation per
  decision beyond adblock-rust's own request parsing.
- The catalog and resources are read once per process; list text is cached
  under `<profile>/astra/blocker/lists/` and re-read only when an update runs.
- Counters are fixed-size atomics/buckets; no URL, origin or rule identity is
  retained.
