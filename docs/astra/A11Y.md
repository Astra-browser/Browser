# Accessibility checklist — P3-T12 (2026-11-02)

Scope: keyboard-only operation, screen-reader names/landmarks, high contrast
(`forced-colors` + the in-app `ui.contrast` switch), reduced motion (OS
preference + in-app `ui.reduce-motion`), and theme-token contrast ratios.
No visual or behavioural redesign: attribute/role/focus-order fixes only.

Evidence per item is a test (`bun run test` = unit, `test:component` =
browser) or a dated manual note. Files are `ui/app/...` unless noted.

## Keyboard

- [x] **Tab order is shell-complete: skip link → address field → tabs →
      content → dialogs.** The skip link (`Shell.svelte`, `.skip-link`) is the
      first tab stop and moves focus to `main#astra-stage` (`tabindex="-1"`),
      past the whole tab column. DOM order already runs urlbar → tabs → stage →
      dialogs (dialogs render last). Evidence:
      `src/app/browser/tests/ShellA11y.component.test.ts` ("keyboard order…").
- [x] **No keyboard traps: every browser-owned modal loops Tab over its own
      buttons.** The sheet variant of `PagePermissionPrompt` already trapped Tab
      (window-level loop); `PromptSheet.svelte` (webext access/review prompts)
      now uses the same window-level loop, so Tab on the last button returns to
      the first and Shift+Tab on the first returns to the last — while the sheet
      is open focus never reaches the (inert) page behind it, and Escape still
      dismisses. Evidence:
      `src/features/webext/tests/WebExtensionFocusLoop.component.test.ts`
      (3 tests: forward wrap, backward wrap, full-cycle containment).
- [x] **Escape dismisses every modal.** Permission sheet, PromptSheet
      children (access/review), onboarding, welcome. Evidence: pre-existing
      `WebExtensionReview.component.test.ts` ("Escape cancels…") +
      `PagePermissionPrompt.component.test.ts`; manual note 2026-11-02: all
      prompt components handle `Escape` on `svelte:window`.
- [x] **All controls are native keyboard elements.** Buttons/inputs are real
      `<button>`/`<input>`/`<a>`; menus (`Menu.svelte`, bits-ui), switches,
      segmented controls (`role=radiogroup` + roving `tabindex`), sliders and
      selects delegate focus to bits-ui primitives. Evidence: tab-order test
      above; `svelte-check` passes with a11y warnings fatal (any non-focusable
      handler would fail `bun run check`).
- [x] **Visible keyboard focus everywhere.** `:focus-visible` draws
      `var(--color-ring)` on buttons/roles/options; inputs show field-focus
      state; tab rows use an inset ring; forced-colors switches the ring to
      `Highlight`. Evidence: `styles/global.css` (+ `+3` forced-colors blocks),
      `TabRow.svelte` (`:focus-visible`), unit test
      `src/domain/appearance/tests/a11y-tokens.test.ts` ("forced-colors…").

## Screen reader (names, landmarks, live regions)

- [x] **Landmarks: `complementary` sidebar, `navigation` tab lists, `search`
      address field, `main` stage, `toolbar` legacy shell.** `Sidebar.svelte`
      (`aside[aria-label]`), `TabList.svelte` (`nav[aria-label]` per section),
      `AddressField.svelte` (`form[role=search]` + labelled input), one
      `main#astra-stage` per visible stage, `ui/shell` bar `role=toolbar`.
      Evidence: `ShellA11y.component.test.ts` ("landmarks…").
- [x] **Every icon button has an accessible name.** `IconButton` requires
      `label` (rendered as `aria-label` + `title`); tab rows name
      `tab.title || untitled`; close buttons name the tab; audio/capture controls
      expose mute/capture state. Evidence: pre-existing component tests assert
      `aria-label`/`aria-pressed`/`aria-expanded` (`AudioControl`,
      `CaptureControl`, `RailDrag`, `SidebarLook`, `SitePanel`, `SpaceBar`…).
- [x] **Status is announced, errors assert.** `SidebarNotice` is
      `role=status`; find match count is `role=status aria-live=polite`;
      navigation failure, move failure, permission failure and render-boundary
      failures are `role=alert`; address errors use `aria-invalid` +
      `aria-describedby` → a visually-hidden `role=alert`. Evidence:
      `ShellA11y.component.test.ts` ("status notices…"); source audit
      2026-11-02 (`Shell`, `AddressField`, `SiteHead`, `RenderBoundary`).
- [x] **Decorative content is hidden.** Favicons, glyphs, masks and motion
      doubles carry `aria-hidden="true"` (`FavIcon`, `Icon`, `AccountSummary`
      meter fill, `list-motion`/`plate-glide` flyers, `SkyLight`). Decorative
      imagery uses empty `alt` (`WebExtensionReview` badge, access icon).
      Evidence: source audit 2026-11-02; `svelte-check` a11y pass.
- [x] **Meters and switches expose values.** Quota meter is `role=meter`
      with min/max/now (`AccountSummary`); zoom is `role=group` with a live
      `output` (`SiteDetailsBody`); toggles use `role=switch`/`aria-checked`
      (`SitePanel` tests). Evidence: `NewTabLook`/`NewTabAccountLook` meter
      assertions.
- [x] **Dialogs are labelled.** Every `alertdialog` carries
      `aria-labelledby` (+ `aria-describedby` where detail exists) and
      `aria-modal="true"` for sheet variants; the in-sidebar permission card is
      correctly non-modal (chrome stays usable). Evidence: focus-loop test
      asserts `role=alertdialog` + `aria-modal`; `PagePermissionPrompt`
      component tests.

## High contrast

- [x] **`forced-colors: active` is supported, not just present.**
      `global.css` re-grounds the page (`Canvas`/`CanvasText`), forces a
      `Highlight` focus ring, and outlines selected rows; ten shared
      controls/sheets add `ButtonText`/`Highlight`/`CanvasText` rules
      (Button, Checkbox, Chip, SearchField, SegmentedControl, AudioControl,
      Badge, CaptureControl, SettingsGroup, Select via Menu/Button sheets).
      Evidence: `a11y-tokens.test.ts` ("forced-colors…") counts the global
      blocks and greps each component/sheet.
- [x] **In-app contrast switch raises text to full.** `data-contrast="true"`
      maps `--color-muted`/`--color-faint` → `--color-text` and hairlines to the
      strong border (`axes/contrast.css`). Evidence: `a11y-tokens.test.ts`
      ("high-contrast axis…").

## Reduced motion

- [x] **OS preference and in-app setting both collapse motion.**
      `axes/motion.css` honours `prefers-reduced-motion: reduce` and
      `:root[data-reduce-motion="true"]` (set by `theme.setReducedMotion` from
      `ui.reduce-motion`); durations collapse to `0.01ms` so
      `transitionend`/`animationend` still fire; list/sidebar/sheet animations
      add explicit `none` guards. Evidence: `a11y-tokens.test.ts`
      ("reduced motion…") + `ShellA11y` ("reduced-motion setting…",
      attribute round-trip).
- [x] **JS-driven motion respects the same switch.** `motion.ts`,
      `still.ts` and `Sidebar.svelte` (`slides()`, `reducedMotion()`) skip
      slides/glides when the preference or setting is on. Evidence: source
      audit 2026-11-02 (manual note — no DOM in the unit project).

## Theme-token contrast (programmatic, WCAG 2.1 §1.4.3/§1.4.11)

Measured by `a11y-tokens.test.ts` against the stylesheets themselves
(composited `rgb(.../α)` over the page ground). Dark ground `#1a1a1d`,
light ground `#f1f1f3`:

| Pair                       | Dark | Light         | Floor                  | Result                |
| -------------------------- | ---- | ------------- | ---------------------- | --------------------- |
| text / page                | 15.8 | 15.1          | ≥ 7                    | pass                  |
| label-secondary / page     | 12.2 | 6.6           | ≥ 4.5                  | pass                  |
| muted / page               | 7.9  | 4.6           | ≥ 4.5                  | pass                  |
| accent (= lit rung) / page | 14.9 | 14.1          | ≥ 4.5                  | pass                  |
| on-lit / lit               | 15.5 | — (same pair) | ≥ 4.5                  | pass                  |
| danger / raised card       | 5.8  | 4.9           | ≥ 4.5                  | pass                  |
| danger / page              | 7.2  | **4.37**      | ≥ 4.0                  | marginal, light       |
| warning / page             | 9.3  | **4.42**      | ≥ 4.0                  | marginal, light       |
| success / page             | 9.0  | **4.33**      | ≥ 4.0                  | marginal, light       |
| info / page                | 8.9  | **4.26**      | ≥ 4.0                  | marginal, light       |
| faint / page               | 4.05 | 2.55          | ≥ 2.5, decorative-only | pass with restriction |

- [x] **Essential text clears AA in both themes** (unit test, floors above).
- [x] **Light-theme status hues recorded as marginal** (4.26–4.42 on the
      page ground): fine on raised cards (danger 4.93), but page-ground status
      labels sit just under 4.5. No token change made (visual change, out of
      lane): remediation is a design-lane token tweak (darken light
      `--color-danger/-warning/-success/-info` ~5%). The unit test pins a 4.0
      floor so a regression fails loudly.
- [x] **`--color-faint` restricted to non-essential use** (placeholders,
      captions, decorative marks — never essential labels; placeholders always
      pair with a visible label). Test pins a 2.5 invisibility floor.

## Known gaps (not fixed — out of lane)

- `TabsSleepingBadge` name is a hardcoded English string ("Sleeping tab …
  select to wake") instead of an i18n message. Cosmetic for screen-reader
  localisation; needs a messages entry + locale translations (P3 locale
  lane owns it).
- Spot `title`-only tooltips on icon glyphs inherit the accessible name;
  no `title`-without-label instances found in the audit, but new icon-only
  controls must keep passing `label` (enforced by `IconButton`'s required
  prop and `svelte-check`).
