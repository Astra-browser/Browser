| D-32 | **The product UI is a first-party chrome document, not a page on top of Firefox.** `ui/app` ships as `chrome://astra/content/app/browser-chrome.html` (jar.mn) and is embedded in the main window as a chrome-privileged iframe; the bridge imports the Host API directly (`resource://astra/host/HostAPI.sys.mjs`). The earlier `file://` remote `<browser>` + framescript relay is deleted. Enabling change: patch **ASTRA-0006** exempts documents whose URI begins `chrome://astra/` from the *default* system-principal `innerHTML` sanitization (`nsContentUtils.cpp`), because Svelte compiles every template through `template.innerHTML`; explicit `setHTML`/`setHTMLUnsafe`/ParserUtils callers keep their own flags. | Decided 2026-11-03 (owner direction: real integration, no duct tape). Live proof: `tests/contract/shell_app_chrome.py` 11/11 PASS — chrome:// document, Svelte root rendered, host mode, no relay, no `file://` browser |
| D-33 | **Boot has no fallback-chrome flash.** The shell's interim titlebar/toolbar/sidebar/split/status strip is a *failure-only* surface: `data-app-booted="pending"` hides all of it and the app's own ground colour fills the window until the app announces `ready`. The window therefore paints the product UI (or its own "Loading…" state) from the first frame. | Decided 2026-11-03 (owner reported a skeleton flash). Proof: early captures at 0.7/1.2/2.0/3.5/7.0 s in `out/headed-early/` |
