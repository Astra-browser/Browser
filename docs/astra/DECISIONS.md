| D-41 | **Profile switching is an in-window space transition, not a profile-directory change.** A running Gecko process cannot change `ProfD`, and launching another instance violates the "same window" requirement. Each profile therefore browses in an Astra space backed by a Firefox container: switching activates that space in the current window, keeps the tabs of the profile left behind, and partitions cookies, sign-ins, localStorage/IndexedDB and the HTTP cache per `userContextId`. Preferences, extensions and the Places history database remain shared by the one running directory; the Profiles copy says so and `docs/astra/STATE.md` records the limit. The binding (profile id → space id) lives in `astra.profiles.spaces`; creating/deleting a profile creates/removes its space (and container data), and `space.switched` keeps the roster's `current` in step. | Decided 2026-11-07 (owner: "the profile that are there should be switchable in a window"). | D-44 | **A profile owns many spaces; a space belongs to one profile.** Spaces are no longer 1:1 with profiles (D-41's binding becomes the profile's *home* space). `SpaceView.profile_id` and `SpaceSnapshot.profile_id` carry immutable ownership; the running profile adopts pre-ownership spaces once, and every later space is created inside the active profile. Each space keeps its own container (cookies, sign-ins, localStorage/IndexedDB, cache), its own bookmark tree, and its own tabs. **Settings → Spaces** creates/renames/deletes/switches spaces, imports bookmarks between spaces of one profile, clears one space's site data, and lists other profiles. Because Firefox's login manager and form-history store are global per origin, `mozilla.cfg` disables them (password managers / OS vault instead, per `PASSWORD_DECISION.md`) so a credential saved in one space cannot fill in another. | D-46 | **Chrome packages are verified and adapted by Rust in `astra-core`, then installed by the engine's own `AddonManager`; Firefox add-ons keep the signed-XPI path.** CRX3 is parsed and its RSA proof verified (1024–8192-bit legacy keys included), the ZIP is unpacked with traversal/size/ratio bounds, and the manifest is rewritten only where Gecko 153 differs (`service_worker`→event page, `side_panel`→`sidebar_action`, MV3 callback form via a generated prelude, static `importScripts` expanded, unsupported permissions removed and reported).
