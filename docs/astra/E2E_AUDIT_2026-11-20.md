## 1. How this was run

- The Windows dev build was rebuilt from source before testing and again after
  every fix round: `bun run --filter @astra/frame build:chrome`,
  `bun run --filter @astra/shell-hello build`, `forge overlay`,
  `mach build faster` (`D:\astra-build\obj-astra-windows`).
- Live work drove the packaged dev build
  (`engine\obj-astra-windows\dist\bin\firefox.exe`) over Marionette, one
  profile and one port per lane, and captured the **real top-level window**
  through Win32 `PrintWindow` (not a DOM screenshot).
- The per-user installed copy (`%LOCALAPPDATA%\Programs\Astra`, build
  2026-11-15, `astra.version` 0.1.755) was smoke-tested read-only.
- 13 lanes ran in parallel: requirements, unit/logic, integration/contract,
  security, UI/UX static, observability/teardown, E2E journeys A (browsing,
  tabs, spaces, split) and B (panels, settings, privacy, keyboard), fuzzing/
  chaos, state/race, performance/memory, live visual/a11y, legacy probe suite.
  The orchestrator triaged, fixed and re-verified every claim before recording
  it (see §5 for claims that did not survive verification).
- Environment: Windows 11 x64, 31 GiB, `example.com` does not resolve on this
  network (the test rig blocks it) — that is why some checks use local
  servers; Google serves CAPTCHAs to automated queries.

## 2. Confirmed defects and what was done

Severity: P0 crash/data loss/security · P1 surface broken or unreachable ·
P2 wrong/misleading/ugly · P3 nit. "Fixed" means it was re-verified on the
rebuilt binary, live, after the change.

### P1 — a failed navigation showed Firefox's own `about:neterror`

Repro: type `http://nonexistent-host-astra-audit.invalid/` (or a refused port).
Actual: Gecko's "Server Not Found"/"Blocked Page" document with the Firefox
mascot and English copy; Astra's `NavigationError` pane never appeared.
Cause: `Content.sys.mjs onErrorPage` passed the **failed address** to
`DialogPrompts.netErrorFor`, which only accepts `about:neterror`/`about:blocked`
(it needs the `e=` reason), so it returned false; `onStop` reads
`browser.documentURI` but Gecko emits no `STATE_STOP` for the error document
(verified with an independent progress listener).
Fix: read the committed error document with a bounded retry.
Verified: Astra's pane with its own copy and "Try again"; native deck hidden
(`data-astra-stage=app`). `out/audit/verify/02-failure-*.png`.

### P1 — Ctrl+L and the sidebar search button did nothing on a page

Cause: `launcher_edit` had a binding but no host route, no `Launcher.edit`, and
no overlay seed; the rejection was swallowed.
Fix: host `Launcher.edit` (http/https only, emits `ui-command
launcher.edit=<url>`), route table entry, overlay seed + select-all, and a
field-focus fallback when the hand-off is refused.
Also fixed while there: **Enter in the launcher always ran the first (search)
row**, so a typed address could not be opened — Enter now submits the typed
words to the host's resolver unless the person moved the cursor.
Verified: `out/audit/verify/05-launcher-ctrl-l.png`, 14-check
`tests/contract/launcher_edit.mjs`.

### P1 — the light-theme focus ring was 2.02:1, and icon controls had none

`outline: none` on `.chrome-button/.window-button/.icon-button` beat the global
`:where(...)` ring (zero specificity), and the light `--color-ring` was a 50%
wash (2.02:1; also in the tint axis).
Fix: restate `:focus-visible` at component specificity; solid accent ring in
tokens and `styles/axes/tint.css` (5.06:1).
Verified: Tab into the chrome → `solid 1.6px rgb(79,93,240)` on every icon
button (`out/audit/focusring`); token is `#4f5df0` (verify.py).

### P1 (visual) — a slow page load replaced the whole chrome with a skeleton

Cause: the shell's `.load-skeleton` was a **sibling** of the content card, and
the card's inset is only applied to `.astra-content`; once the app frame draws
the sidebar itself, the skeleton resolved against the full main column. During
any slow load the sidebar, address bar and tabs disappeared.
Fix: the skeleton now lives inside the content card (clipped by its radius).
Verified: skeleton rect = the card `[276,8,982,837]`; chrome stays visible
(`out/audit/slowload/1-load.png`).

### P1 (data) — a deleted space came back after restart

Cause: `Metadata.save()` refused every capture with no http(s) tab
(`empty_capture`), so deleting the page-holding space (or renaming from a New
Tab) never persisted; the quit `flush()` then rewrote the pre-change snapshot.
Fix: allow an empty-tab capture only when the space list differs from the last
saved snapshot, and never before a first save; `flush()` writes the current
organisation in that case. `organisationDiffers()` is exported and covered.
Verified: `out/audit/race/probe_m.py` → restored spaces contain only
`space-1`; `metadata_restore` 78 checks.

### P1 (tooling) — `forge build --os windows` could not run at all

`cmd.exe` mangled the embedded quotes of the one-argument build script
(`The syntax of the command is incorrect`); the two staged toolchains were never
exported; a fresh mozconfig reconfigured without `--with-wasi-sysroot`.
Fix: write the script to `out/.forge-build-windows.sh` and pass only
`bash <path>`; export `MOZ_WINDOWS_APP_SDK_DIR`/`MOZ_WINDOWS_RS_DIR` from env
or the documented staging paths; reuse the objdir's `.mozconfig`.
Also: `astra-core` is now staged beside a running binary and swapped by
`Boot.launchCore` before the next launch (in-place replace fails with
`os error 32` while a browser is running).
Verified: `forge build --os windows --faster` → `build: done` (exit 0), core
installed.

### P2 — the launcher's arrow-key selection painted nothing

`var(--color-hover)` never existed, so the declaration was invalid and the
cursor was transparent. Now `--color-fill-active`. Verified: selected row has a
non-transparent background (verify.py).

### P2 — a failed feature-switch save said nothing

`FeatureSwitch` never read `preferences.saveFailed()`. It now shows
`settings_save_error` in a `role="alert"` under the row.

### P2 — the sidebar picker offered "Compact", which hid the column

`chosen()` adopts a stored `compact` as hidden (the rail was retired), but the
picker still wrote `compact`, so choosing it made the sidebar vanish with no
rail. The row now offers Expanded/Hidden and maps a legacy `compact` to Hidden.

### P2 — the hidden sidebar's reveal worked only from x 8–16

A z-200 native drag `<box>` covered the outermost 8 px of the 16 px reveal
strip. The left edge box is gone (the top bar and the sidebar itself are the
drag surfaces on that side).

### P2 — a parked split lost its menu rows

`inSplit()` read only the split in front, so right-clicking a pane tab of a
split parked behind another tab showed "Open in Split View" again. It now reads
every split group, and End/Save only appear for the split in front.
Verified: `out/audit/split-menu/parked-split-menu.png` — the menu offers
Replace/Remove and no End/Save.

### P2 — downloads froze after Pause → Resume

The revision ranked states by name (receiving 1 < paused 2), so every frame
after a resume looked older than the paused one and the app dropped it; the row
stayed paused and jumped to Completed. Revisions now carry a per-transfer
generation that grows on every state change. Covered by 4 new contract checks
(`downloads_model` 130).

### P2 — a failed tab was named with Firefox's English title

`TabAttrModified` projects the native tab's `label`; the engine sets it to
"Problem loading page" after a failure. With a covering failure the host is the
label now (row **and** window title).
Verified: row and window title both `nonexistent-host-astra-audit.invalid`.

### P2 — no visible Stop control while loading

The nav control stayed "Reload"; only Ctrl+. stopped. It now becomes "Stop
loading" while `tab.loading`, and clicking it cancels (verified: `loading:false`).

### P2 — bookmarks accepted `javascript:`/`data:`/`about:`

A row that can never be opened (the opener treats unknown schemes as a search)
and a script payload. `addLink` now allows http(s)/file only; 3 new contract
checks (`bookmarks_model` 195).

### P2 — a background tab in a new split could stay blank

`ensurePaneLoaded()` loaded once; if the background browser was still being
created the load was dropped. It now retries (0/120/240/360/480 ms) while the
document is still blank, never reloading a page the person stopped.

### P2 — a resumed download left a ghost row

`idOf()` keyed the wire id on `startTime`, which the native transfer rewrites
on resume, so the row forked and the ghost's Cancel could not reach anything.
The first id a native transfer is given now sticks to it (WeakMap), and the
revision generation from the fix above keeps progress monotonic. Covered by
6 contract checks (`downloads_model` 132).

### P2 — an internal page's last action sat under the window controls

Page Source's "Copy source" (1155–1248) overlapped the window-control pill
(1173–1255). The internal toolbar now reserves the caption area
(`padding-inline-end: 150px`).

### P2 — addresses over 32 KB were accepted and silently ignored

`Navigation.loadURL` reported `accepted:true` and `Tabs.create` coerced to
`about:blank`. Both now refuse with `invalid_url` ("the address is too long").

### P2 (packaging) — the uninstall entry had no `InstallLocation`

Apps & Features showed no path. Added `InstallLocation`, `NoModify`, `NoRepair`
to `tools/windows/astra-installer.nsi`. **Not compiled:** NSIS is not installed
here (the 0.1.755 setup.exe predates the change).

### Gate fixes

- `tests/contract/shell_assembly.mjs` required the literal `Frame:`; the shell
  exposes `get Frame()`. The assertion accepts both — contract PASS.
- `.gitignore` had a UTF-8 BOM on line 1 (so `folder_context` never matched);
  removed.
- New contract `tests/contract/launcher_edit.mjs` (14 checks) and 11 new checks
  across `metadata_restore`, `downloads_model`, `bookmarks_model`.

### Pre-existing branch work (not from this audit, kept and verified)

The branch already carried an uncommitted tab-switch seam fix (LazyView module
cache + no vertical card transition + idle New Tab warm-up). Its component test
passes (3/3) and the tab-switch probes show no skeleton flash.

## 6. Not verified (honest limits)

- Permission prompt, WebRTC prompt, PiP, audio/video playback, passkey UI and
  DevTools automation were not driven end-to-end here (no camera; media needs
  an autoplay pref; PiP needs ffmpeg fixtures). The geolocation prompt **was**
  verified live: a loopback page's request raises Astra's own
  `[data-astra-page-permission-prompt]` with its three choices and **no**
  native `tabmodalprompt` (`out/audit/permissions/geo-prompt.png`). The legacy
  probes for some other prompt kinds ran and passed; the rest are listed in
  `out/audit/findings/probes.md`.
- The NSIS installer change was not compiled (NSIS not installed).
- 2×2 split / four panes is not a capability (`MAX_PANES=3`); the visual lane's
  "2×2" request tested a non-feature.
- macOS is out of scope.
- Results from lanes that overlapped the fix rounds describe the binary as it
  was when each scenario started; the fixed behaviours were re-verified
  afterwards by the orchestrator (verify.py + the focused probes above).
