## 3. Defects found and fixed (each verified before and after)

Four independent reviews ran in parallel (host modules, UI state/wiring, engine
patch security, full unrouted inventory). Verified findings, fixed permanently:

**Native UI is the only UI**
- A window-less or pre-bootstrap auth challenge inside an Astra window no
  longer opens Firefox's auth dialog — it fails closed.
- WebRTC for an unmodelled tab fails closed instead of the native doorhanger.
- A granted origin can no longer start the camera/mic from a background tab
  without a prompt (upstream defers that to the doorhanger's `showing`).
- The window registries use realm-safe checks and are removed on window
  `unload`; uninstall also settles that window's pending requests.

**Engine requests can never hang**
- Auth is bound to its channel (`loadGroup` observer) plus a 120 s bound, so an
  aborted fetch/iframe settles the engine prompt.
- Cert pending state clears on `nav.committed`, is fenced to the failed URL and
  uses the owning browser (no `Services.wm` scan across windows).
- Stale-document permission answers now cancel the engine request.
- Core calls have an 8 s bound; `Metadata.save` can no longer wait forever.

**State correctness**
- Every `Tabs.*` mutation answers an `OperationAdmission` — Work "browse" and
  menus no longer report a rejection after a successful tab action.
- `certificate_exception` is origin-scoped and cleared on a different origin.
- `tab-changed` carries a full `TabView`, so mute/capture/failure deltas reach
  the app (`astra:tab` is forwarded).
- `page_find` is routed and `nav.find-result` reaches the find bar.
- Tab moves use the space-scoped row index, not the global order.
- Closed tabs are pruned from the revision map; a delta for an absent tab is
  ignored; a presentation cannot set an active id that is not in the snapshot.
- `deleteSpace` announces each tab's own window.

**UI cannot wedge**
- Extension install: `try/finally` on review/confirm/access, a refresh epoch,
  and a real `dispose()` (timers, queue, flags).
- A refused sign-in keeps the typed credentials instead of blanking them.
- A "still applying" permission disposition clears the busy flag.
- A rejected permission host report retries instead of leaving the layout flag
  stale.
- The site-access editor always closes, even when the engine refuses.
- Fire-and-forget tab intents no longer raise unhandled rejections.

**New wiring (was `unknown_command`)**
- `tabs_answer_page_request` (popup / external app / hung page).
- `web_extension_prepare` (AMO review; Chrome Web Store answered with a real
  error), `retry`, `review_update`, `set_access`, `set_pinned` (pref-backed and
  projected), `answer_access`, `store_button`.
- `page_find`.

**New guards**
- `tests/contract/wire_coverage.mjs`: every route target exists, the channels
  this merge owns are forwarded, and any *new* unrouted command or unforwarded
  channel fails against the recorded baseline (`wire_baseline.json`).
- `tests/contract/tabs_admission.mjs`: all tab mutations admit, cert flag is
  origin-fenced.

## 4. Performance

`out/perf-final/SUMMARY.md` (2-run, headed engine):

- startup cold 0.302 s / warm 0.301 s
- 1 tab 491 MiB; 10 tabs 407 MiB; 50 tabs loaded 448 MiB; 50 sleeping 609 MiB
- scroll-step median 16.0 ms / p95 17.0 ms; rAF 21/s
- blocker in-process p50 2.14 µs / p95 2.68 µs / p99 3.75 µs over 131 724 rules
- tab switch median 43.5 ms / p95 142.5 ms in that pass — the immediately
  preceding pass measured 18.9 / 52.9 ms, and the UI tour's per-action switches
  are ≤ 20 ms. The 2-run pass shared the machine with a separate 17-process
  desktop Firefox session; see `docs/astra/PERF.md` §8 for the caveat and the
  proposed quiet-machine confirmation.

Perf work in this pass (no quality trade): per-tab deltas instead of full
snapshots for single-tab changes, revision pruning, an epoch on extension list
refreshes, one host lookup per window, and bounded core calls so a wedged
sidecar cannot stall saves.

## 5. What is still open (honest list)

`docs/astra/KNOWN_LIMITS.md` is the authoritative list. Summary:

- **Firefox-owned surfaces:** save-password doorhanger (decision pending),
  print window.
- **No producer yet:** popup blocking and external-protocol cards (the answer
  route exists and refuses a card that is not on screen).
- **Unwired UI inventory:** 200 command ids (account, Work model/human/sites,
  blocker, page assist, voice, profiles, import/export, updates, menus,
  split/drag-drop, downloads manager, media import). `wire_coverage` freezes
  this set so it cannot grow unnoticed; P8/P10 own the backends.
- **Multi-window organisation:** one writer per process; a second window's
  spaces/pins are not merged into the store yet (P5b-3).
- **Tab folders:** UI keeps them in `localStorage`; the Rust folder model is
  not wired.
- **Page source:** shell driver is still the privileged `fetch` (fresh GET, not
  the tab's cached document). Private windows are refused. Native view-source
  is P8-1b.
- **Background visibility:** the stress matrix still records parked pages
  reporting `visible`; worth a dedicated throttling pass.
- **Media probe** needs a headed machine with an audio device.
