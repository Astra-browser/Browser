# Spike S-01 decision: `<browser>` placement by CSS (single + multi) — U-05

Status: spike complete (P3-T02). Recommendation: **CSS-grid content slots,
no reparenting**; one remote `<browser>` per cell, layout switches toggle
`data-layout` + cell `hidden` only.

## Question

Can one AND many `<browser>` elements be positioned by CSS into Astra's
content slots (split/Work panes) without reparenting — with resize, focus
switch, devtools, and IME/zoom staying sane? Or must we use Firefox's
split-view wrapper primitives / a minimal tabpanels patch (fallback)?

## Method

- Pinned-source grounding (read directly, no guessing):
  - `engine/toolkit/content/widgets/browser-custom-element.mjs`:
    `connectedMoveCallback()` is an explicit no-op so moving a `<browser>`
    in the DOM does **not** destroy/reconstruct it (bug 2007742), while
    `disconnectedCallback()` → `destroy()` kills the docshell. Our design
    goes further and never moves nodes at all — layout is pure CSS.
  - `engine/browser/components/tabbrowser/content/tabbrowser.js` wraps each
    browser in stack/vbox/hbox (`browserStack`/`browserContainer`); Astra
    needs none of that — P1-T10 proved a standalone remote browser works.
  - `engine/browser/components/tabbrowser/splitview/` contains only
    `triage.json`: **no reusable split-view primitives exist** on this ESR.
    The fallback would be a minimal tabpanels-style patch, not reuse.
- Prototype (this branch, newly owned files only):
  - `overlay/astra/chrome/slots/Slots.sys.mjs` — model (`layoutFor`,
    `createSlotsState`, `bindTab`, `slotForTab`) + `mountSlots` live DOM
    binding. Fixed pool of `maxSlots` browsers, each permanently parented
    in its grid cell; 1→2→4 switches only set `data-layout`/`hidden`.
    Tab↔slot binding is model-side; rebinding loads a URL into the cell's
    OWN browser. Resize flows through `ResizeObserver` → `onRect` (feeds
    `Panes.setRect`); focus via `browser.focus()` + `Tabs.select`.
  - `overlay/astra/chrome/slots/slots.css` — `single` / `cols-2` /
    `grid-2x2` variants. Browsers flex-fill their cell (`min-*: 0` keeps the
    grid inside the chrome window; same XUL-flex lesson as P1-T10 — sizing
    flows from the flex/grid parent, never `position:fixed`).
- Proof:
  - `tests/contract/slots_model.mjs` — stdlib Node stub: real Host API
    Tabs/Navigation/Panes + fake DOM. 39 checks.
  - `tests/contract/slots_live.py` — stdlib Python live probe in the built
    Astra window (1→2→4 real remote browsers in a CSS grid). 16 checks.

## Decision

**Ship the CSS-grid slot layout for split/Work panes (confirms the U-05
plan).** No sub-case failed, so the tabpanels-fallback patch is NOT needed:
no reparenting ever happens (stronger than the `connectedMoveCallback`
guarantee), hidden cells keep their docshells (same mechanism as
background tabs), and per-pane navigation/zoom/focus/contexts are
independent by construction (one docshell per cell, one history stack per
`astra_tab_id`).

Caveats recorded honestly:

- **IME**: not drivable headless. Reasoned safe: IME binds to the focused
  docshell's widget; focus demonstrably moves between panes and each pane
  owns a full remote docshell (identical to tab-switch, which Firefox
  supports). Manual follow-up on a real window before P3-T06 closes.
- **Devtools toolbox UI**: not opened headless (no GUI harness). Proven
  instead: every pane exposes a distinct live `browsingContext` +
  `frameLoader`, which is exactly what a toolbox targets. Same manual
  follow-up as IME.
- **Panes wiring**: the prototype drives layout through the Tabs model and
  `Panes.setRect` for geometry; full `Panes.attach(slot)` wiring per split
  belongs to P3-T06 (split persistence), which consumes this spike.

## Finding F-01 (load-bearing, OUTSIDE this lane — flagged, not fixed)

`overlay/astra/host/Content.sys.mjs` (P2-T06 v1 rewrite) changed `XUL_NS`
from `...there.is.only.xul` to `...there.is.only.xhtml`. Verified live:
`createElementNS` with the `.xhtml` namespace returns a **plain Element
that never upgrades** — no `fixupAndLoadURIString`, no docshell — while
`.xul` yields `MozBrowser` immediately (matching `createXULElement`).
The shipped binary still contains the correct `.xul` line, so P1-T10 live
is green today; but the **next engine rebuild/repack ships the dead
browser**. Owner of `host/Content.sys.mjs` (or orchestrator): flip the
constant back to `.xul` before the next build. This spike's
`Slots.sys.mjs` and `slots_live.py` already use the verified `.xul`
namespace, and the live probe asserts `ctor === MozBrowser` as a
regression guard.

## Per-OS notes

Proven on Linux headless. macOS/Windows deltas are not expected: grid
sizing, `hidden`, `focus()`, `ZoomManager`, and remote docshells are all
platform-independent chrome/DOM mechanisms (same reason P1-T10 needed no
per-OS work). Re-run `slots_live.py` on each OS at P3-T06 time; no
code fork anticipated.
